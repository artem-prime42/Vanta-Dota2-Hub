# Special client patches (Weather and Towers)

VANTA keeps these entries separate from ZIP/VPK cosmetic installs. Catalog items use `modType: "special_patch"`, `specialType: "weather" | "tower"`, a source revision, and `requiredFiles` descriptors containing the upstream item-definition URL, numeric Dota item ID, and Git blob SHA-1. New variants can be added in catalog data without adding per-mod application logic.

## Upstream behavior reviewed

At the pinned h6rd/Patcher revision `bab71ddfaff0033e1cffef1134764ecb4e39f24e`, `Patcher.py`:

1. Reads `scripts/items/items_game.txt` from `game/dota/pak01_dir.vpk`.
2. Replaces item records by numeric ID: Weather uses ID `555`; Towers use Radiant `677` and Dire `678`.
3. Builds a VPK containing the override at `scripts/items/items_game.txt` and places it at `game/DotaModdingCommunityMods/pak01_dir.vpk`.
4. Adds `Game`/`Mod` search paths for `DotaModdingCommunityMods` to `game/dota/gameinfo_branchspecific.gi`.
5. Backs up and appends a `dota.signatures` line containing the SHA-1 and little-endian CRC32 of the resulting `gameinfo_branchspecific.gi`.
6. Validates an existing patch by checking the Patcher marker and comparing those recorded hashes with the current gameinfo file. It does not compare a Dota build number with a mod version; a game update generally replaces one or more patched files and Install must run again.

VANTA follows the same item-game override and search-path/signature-hash contract. It additionally pins and verifies every fetched upstream definition, checks the Steam `appmanifest_570.acf` build ID when present, hashes the current base `items_game.txt`, and verifies the managed patch VPK and patched client files before reporting the patch current. This avoids relying on a mod version comparison alone.

The override file layout is platform-specific: Windows writes only `game/DotaModdingCommunityMods/pak01_dir.vpk`, matching Patcher; Linux writes that file plus the `pak01.vpk` alias required by the verified Linux runtime mount. The Windows-only alias is intentionally not generated. Base `items_game.txt` decoding follows Patcher's UTF-8 `errors='ignore'` behavior.

`diagnostics/windows-weather-2026-10-04/package-smoke-report.json` records an isolated Windows-layout package run using the installed Dota base VPK and clean backups: the generated `items_game.txt` matched the pinned-Patcher reference byte-for-byte, the VPK verified with exactly one entry, only `pak01_dir.vpk` was produced, `win64/dota.signatures` matched the exact gameinfo bytes, and uninstall/rollback restored the isolated baseline. The same run verified Linux still emits both filenames and restores cleanly. This is package/client-file verification only, not Windows game runtime verification; the Linux host has no `game/bin/win64/dota2.exe`.

## VANTA ownership and safety

- The unmodified `pak01_dir.vpk` is read only. Windows receives only the Patcher-compatible `pak01_dir.vpk`; Linux receives that plus the runtime-required `pak01.vpk` alias.
- Original `gameinfo_branchspecific.gi` and the selected `dota.signatures` snapshot are kept under VANTA user data. Windows prefers `bin/win64/dota.signatures`; Linux prefers `bin/linuxsteamrt64/dota.signatures` and falls back to an existing `bin/win64/dota.signatures` if the Linux copy is absent, matching the upstream Patcher's folder selection. VANTA never creates a missing signature database and fails safely if neither exists. Existing installs are migrated if the selected signature file changes. A pre-existing Patcher VPK is retained and restored on removal.
- Steam installations reached through symlink aliases (for example `~/.steam/steam` and `~/.local/share/Steam`) resolve to one canonical game path for patch ownership and backup lookup. Backups written under a prior alias-derived key are migrated into the canonical backup directory. A separate disposable `--user-data-dir` profile does not own or borrow another VANTA profile's backups; it safely refuses to rewrite an already-patched game if its own original backup is unavailable.
- When VANTA updates `dota.signatures`, it retains the file's existing newline convention; Windows files use CRLF, matching the upstream Patcher's Windows text-mode output.
- Weather entries replace the same item ID, so one Weather can be active at a time. Towers replace both team IDs as one selection. One Weather and one Towers selection can coexist in the combined override VPK.
- Install, Update, and Remove are refused while Dota 2 is running; VANTA does not kill or launch the game.
- File writes are journaled and rolled back on an error. If a game file or managed VPK no longer matches VANTA's recorded hash, removal does not overwrite the changed file. If Steam or another process deletes a VANTA-patched `gameinfo_branchspecific.gi` or changes `dota.signatures`, removal restores only files still owned by VANTA (or missing files) from the original backups. Stale backups are rebuilt from current clean files; if a backup is unusable while VANTA's exact edits remain, removal strips only the owned search paths and the signature for that patched file.
- On Windows, VANTA resolves selections such as the game's `dota` subfolder, Dota app folder, or Steam library root to the canonical `game` directory by locating `dota/pak01_dir.vpk`. Steam discovery checks `SteamPath` and `InstallPath` registry values, including `HKLM\Software\WOW6432Node\Valve\Steam`, and then reads each Steam root's `steamapps/libraryfolders.vdf`. Startup revalidates a saved path and falls back to Steam auto-detection if it is stale. Weather/Tower install/update refuses to start if `gameinfo_branchspecific.gi` or the runtime signature database is missing; verify Dota 2 files in Steam and re-detect the path before retrying.
- Windows patch diagnostics are written to the VANTA application log as structured `special-patch:windows-diagnostics` records for pre-write, installed, and failed stages. They include selected patch types, client target paths, expected/actual VPK filenames, gameinfo/signature hashes, signature-match/count state, and backup hashes; signature contents are never logged.
- On Linux, Settings → Diagnostics → Linux JSON report saves `vanta-linux-diagnostic.json`. It inventories Steam/Dota roots, filesystem and file permissions, both Weather/Towers VPK names, and validates each available override with the project's `vpk-tools` reader (header, entries, CRC, repeated reads, and `verify()`). When Dota is running, it additionally reads `/proc` for PID, executable, working directory, sanitized command line, mount namespace, Steam process/library association, and compares the canonical running install path with VANTA's target; unavailable or ambiguous paths are explicitly `UNKNOWN`. It also compares live and backup gameinfo/signatures and reports categorized log-signal counts; home paths are normalized and environment, log, and signature contents are not exported.
- This modifies game client files and the signature map. It is not represented as VAC-safe; users should understand the risk before installing.

## State and update detection

Installed special records persist `specialPatchState`, `currentVersion`, source revisions, build ID, base item-data hash, generated patch hash, patched gameinfo/signature hashes, and the signature path. At startup and Library refresh, the special-patch service checks these values. A changed upstream source revision, Steam build ID, base item-game data, VPK, gameinfo marker/hash, or signature hash yields `update_required`. Successful rebuilds persist the new metadata and clear the requirement. Runtime `updating` and `error` states are owned by the same service.
